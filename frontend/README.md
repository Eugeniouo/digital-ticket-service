# Электронная очередь — frontend-прототип

HTML, CSS и JavaScript ES modules без фреймворка. Для проверки использовался Node.js 24.
Установка npm-зависимостей для запуска не нужна. Библиотеки QR включены локально.

## Запуск и проверки

Из папки frontend:

```sh
npm test
npm run build
npm run dev
```

Локальный адрес: http://localhost:4173/. `server.mjs` предназначен только для
локальной разработки, не для публичного размещения. Не храните секреты в его
рабочем каталоге и не публикуйте этот сервер в интернете.

## Сценарии

- Главная: предварительная запись, QR-сканер, вход сотрудника.
- Предварительная запись: отделение → услуга → дата и время → демонстрационный талон.
- QR: `/src/scan.html` распознаёт ссылку вида `/src/visitor.html?department=<uuid>`.
  Генератор в кабинете руководителя привязан к его отделению. Для телефона нужен
  опубликованный HTTPS-сайт, не localhost. Камера требует разрешения пользователя.
- При первом входе в браузере создаётся локальный руководитель. Он создаёт операторов
  через раздел «Аккаунты». Роль берётся из аккаунта, не из параметра URL.
- Оператор: вызов, начало/завершение обслуживания, возврат, перенаправление, проблемы.
- Руководитель: обзор, окна, правила, аналитика с календарём, журнал, аккаунты и QR.

## Структура

- `src/home.js` — главная страница и вход в клиентские сценарии.
- `src/app.js`, `calendar.js`, `mock-data.js` — клиентский интерфейс и демо-каталог отделений/услуг в форме API DTO.
- `src/staff.js`, `staff-views.js` — действия и экраны сотрудников.
- `src/operator-accounts.js`, `login.js` — локальные аккаунты и вход.
- `src/report-calendar.js`, `staff-analytics.js` — календарь и демо-отчёты.
- `src/scan.js`, `qr.js`, `visitor.js` — QR-сценарии.
- `src/shared/` — HTML-помощники, обновление DOM и загрузка ресурсов.
- `public/assets/` — изображения и локальные QR-библиотеки.
- `tests/` — автоматические проверки.

## Ограничения и ревью

Это НЕ готовая система очереди и НЕ серверная авторизация. Данные аккаунтов
хранятся в localStorage, роли можно изменить средствами браузера. Используйте
только вымышленные имена и тестовые пароли. Талон посетителя не передаётся оператору.
Расписание, показатели и очередь демонстрационные. Прошлые даты и время
блокируются по локальному времени устройства; реальные слоты должен выдавать API.

## Интеграция с backend

Первый шаг — заменить `mock-data.js` вызовом `GET /api/departments`.
Идентификатор отделения, услуги и талона — UUID; почтовый индекс живёт в `code`,
номер талона — в `ticket_label`. QR и запись передают `department=<uuid>` и
`service_id`. Нужны отдельные контракты входа, слотов, окон и аналитики.
Сервер должен проверять права, выдавать уникальные талоны и хранить состояние.

## Публикация

`npm run build` формирует `dist`. В Netlify: base directory `frontend`,
build command `npm run build`, publish directory `dist`.
Либо загрузите содержимое `dist` вручную. Исходный ZIP не предназначен для Netlify Drop.
Не добавляйте `dist` в Git. Этот деплой публикует только интерфейс, не backend или БД.
